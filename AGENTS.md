# Repository instructions

## Documentation

- Prefer updating existing documentation over creating new files.
- Create a new document only when it has a clear ongoing audience and purpose, or the user explicitly requests it.
- Keep maintained documentation concise, consistent with the implementation, and free of duplicated explanations.
- By default, keep routine plans, progress updates, and completion reports in the chat or pull request rather than creating repository documents.
- Retain logs, screenshots, and other evidence only when needed for reproducibility, regression coverage, release verification, or explicitly requested deliverables. Avoid accumulating routine run artifacts in docs.
