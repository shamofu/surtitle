# Resource synchronization and IPC contracts

## Changes implemented

The previous native five-second `app-changed` heartbeat refreshed the complete app snapshot. Downloads and operation progress also used one-second queries; AI runtime hooks and draft consumers maintained separate three/two-second polling loops. These reads are replaced by the native `data-changed` protocol and shared recovery subscriptions.

Every notification has a protocol version, process epoch, monotonically increasing revision, resource domain and optional entity ID. Command adapters emit only after successful writes; background downloads, operations, tool discovery and AI result application emit at their commit/progress boundaries. Playback positions remain on their separate player channel. Prepared, unapproved auto-estimation quotes remain durable but do not appear as activity jobs.

One native listener per event validates the envelope and shares delivery among consumers. Registration failures retry with bounded exponential backoff. The application recovers on registration, window focus, network resume, visibility resume and one visible-window 60-second checkpoint. A revision gap requests a checkpoint, including when two missing/received events share a domain. Checkpoints contain latest revision per domain; unchanged checkpoints cause no data fetch. A process-epoch change or restore invalidates all persistent queries. An older in-flight patch cannot replace a newer revision or cross a restore/epoch transition; failed reads stay queued with bounded retry delay.

Notifications coalesce for 80ms. Snapshot domains request only their selected fields using `get_snapshot_patch`; media subtitles, draft selections/candidates, transcript reviews, operation progress and downloads invalidate their own entity query keys. Jobs/budget currently share native summary construction, so a jobs-only patch still computes budget internally; it does not list media/cards/tools. Initial load and explicit whole-app refresh/restore retain the full snapshot API. Some older explicit mutation flows still request their existing broad snapshot refresh. Settings and phrase autosave instead merge the native authoritative returned settings/card, preserving unrelated object identities.

Final review reproduced a resource-read race: a query begun before a native commit could return old data during the 80ms coalescing window. Its later completion timestamp incorrectly suppressed invalidation, and an unchanged checkpoint could not repair it. Resource notifications now cancel matching in-flight queries before invalidating them, including initial reads with no cached data; completion wall-clock time never proves revision freshness. Inactive matching queries are marked stale. Refetch errors explicitly reject invalidation so the synchronizer retains those domains and retries with bounded backoff, rather than consuming an event after a failed read. Three regressions cover the completed stale read, a still-pending initial read, and a failed active refetch followed by successful recovery. The focused synchronization/query/event run passed 24 tests.

Draft selection and review consumers now share TanStack Query keys and native invalidation; they no longer poll every two seconds. Active local editing fields remain separate from fetched review data. Native AI chunk application emits `Review` and subtitle/media changes, so received passages become available before a job ends.

## Contract boundary

`node scripts/generate-ipc-contract.mjs` derives all **101** registered command names, parameter names, optionality, primitive/container shape and native return signatures. Its checked named-result mapping refers to existing TypeScript DTO contracts. `check:ipc` and the scripts test verify generated output and parity with Tauri's actual invoke handler. Every production wrapper now infers its result from its command; callers cannot select an arbitrary `call<T>` return type.

The production invoke boundary validates names/argument envelopes and return primitive/container envelopes. `data-changed`, checkpoints and the partial-snapshot field selection have additional runtime validators. **This is not a complete generated validator for every nested legacy DTO field.** Rust serde and native use cases still enforce nested arguments/semantic constraints; the checked TypeScript DTO declarations define consumers' fields. `list_draft_selection_candidates` still returns native `serde_json::Value`; its explicit mapping is to the existing candidate DTO. Those limitations are visible in the generator, rather than hidden by caller assertions.

Shared JSON fixtures are exercised by both real Rust serialization and TypeScript validators: resource events, checkpoints, optional partial-snapshot fields, null/string options, string arrays, empty typed draft arrays and booleans. Compile-only assertions reject unknown commands, wrong argument names, missing required arguments and forged result types. The generated check caught an existing optional embedded-subtitle stream index that Rust required; the frontend wrapper now requires it.

## Validation and measured behavior

At the initial synchronization checkpoint, native application tests reported **116 passed, 2 explicitly ignored local integrations** (`cargo test -p surtitle --lib --no-default-features --locked`). Changes tests cover epoch/revision checkpoints and the shared wire fixtures. Targeted UI tests cover domain identity retention, entity targeting, event bursts, lost same-domain events, stale in-flight patches, stale checkpoints, epoch recovery, listener deduplication/re-registration, late disposal and malformed messages. The later frozen-source full-suite results are recorded in [acceptance](acceptance.md).

The opt-in Chromium diagnostic `SURTITLE_PERFORMANCE=after-card-virtualization` with `redesign-performance.spec.ts` ran the real app with test-only native request interception. The final `final-batched-clean` run reproduced the same request counts with no console errors or browser exceptions. After initial load, a 65-second **virtual-clock** idle interval issued one `get_change_checkpoint` and no full snapshot reads. A burst of 100 player events issued no data calls; 50 operation notifications produced one operation query; 20 job notifications produced one snapshot patch. These are request-count measurements, not CPU/power measurements or a real disconnected desktop process test.

Old cadence, derived from the removed code, was approximately 13 full snapshot reads and 65 reads of each one-second activity query per 65 seconds, excluding overlap/deduplication. That is a code-derived comparison, not a replay of the old application binary. Real native missed-event/process-restart behavior remains an acceptance concern distinct from the tested protocol recovery model.
