# AI, scheduling, and media processing decision record

Evidence reviewed 2026-10-11. This work changes dispatch coordination and the learning interaction. It does not claim that changing providers or replacing the speech engine improves quality without a matched evaluation.

## Decisions and learner outcomes

| Area | Decision | Evidence and consequence |
| --- | --- | --- |
| Paid dispatch | Replace independent competing workers with a native single dispatch lane. | `application/ai/scheduler.rs` grants a turn per request. Single-request text work has priority at chunk boundaries; after three interactive turns, an already queued bulk turn runs. An explanation can start during a transcription, without a false unknown-outcome error or overlapping paid sends. |
| Billing ownership | Retain transactional `charges.sqlite` reservations, frozen request plans, approval IDs, and settlement. | The queue grants scheduling access only. `reserve_next_scoped`, final authorization, source guards, budgets and usage settlement remain authoritative. Approval may queue behind a different in-flight job; same-job live attempts and unknown outcomes remain blocked. Jobs exceeding remaining budget at dispatch stop without sending. |
| Retries and restart | Retain bounded, explicitly scoped 429 retries and conservative unknown holds. | A known active request waits; an unknown outcome stops. The queue is deliberately session-local. Startup recovery revokes interrupted approvals, so reopening cannot silently resend paid work. Local received-output application remains replayable without a new provider call. |
| Send interval | Remove the unconditional 10-second wait; adapt only after observed service congestion. | Six matched serial requests showed no rate-limit benefit from the fixed gate and about eight seconds of extra inter-request waiting. Native single-owner dispatch, 20/40/60-second rejection backoff, longer Retry-After floors and approval/accounting guards remain. |
| AI entry | Replace estimate button → separate review → checkbox → approval with scope + automatic estimate + one Start. | `AiDialog`, `DraftAiDialog`, and `TranscriptionWorkspace` retain the selected inputs beside the estimate. Unknown price is disclosed beside Start; changing scope/model invalidates its bound quote. No paid approval occurs on render, estimate, expiry refresh, or scope edits. Technical sending detail is collapsed. |
| Provider | Retain the existing native Vertex adapter for this change. Compare a local speech adapter before adopting one. | Current authorization, source binding, streaming validation and ledger tests exercise Vertex semantics. A replacement must supply normalized text/timing, usage evidence, interruption semantics, and frozen request identity; matching an HTTP shape alone is insufficient. |
| FSRS | Retain Rust `fsrs` scheduling and existing review history. | `crates/core/Cargo.toml` uses FSRS; the project supplies scheduling and optimization capabilities. The new checked card edit updates only editable text. It cannot overwrite scheduling, review rows or attached audio. Changing algorithms or resetting memory state would add migration risk without a demonstrated learner benefit. |
| Local preparation | Adopt a bounded staged FFmpeg encoder pipeline; retain Silero VAD and immutable audio chunks. | `crates/ai/src/prepare/encoding.rs` starts at most two local encoders while decoding/VAD continues. Only closed pause evidence inside a fully observed decision window can form an early chunk. EOF analysis verifies the entire prefix before a receipt can exist. Source, tool, sample, context, cancellation and price boundaries remain unchanged. |

## Alternatives compared, without assumed superiority

[whisper.cpp](https://github.com/ggml-org/whisper.cpp) offers native C/C++ transcription with several acceleration backends. It is a candidate for a packaged offline adapter and avoids requiring a separate Python environment. It would still add model downloads, CPU/GPU selection, memory limits, timestamp adaptation and cancellation/recovery work. The matched prototype below measures latency, normalized text errors, timestamps and model size on this Windows host. It does not establish accuracy across conversational speech, accents or background music.

[faster-whisper](https://github.com/SYSTRAN/faster-whisper) uses CTranslate2 and a Python-facing runtime; its documented GPU requirements and PyAV audio decoding change the deployment shape. Its published benchmarks are evidence for those exact configurations, not evidence that it beats the existing provider here. Choose between these candidates only with the same clips, language/accent mix, silence/music passages, and timestamp tolerance.

[FSRS-rs](https://github.com/open-spaced-repetition/fsrs-rs) provides simulation and scheduling. Compare any scheduling replacement on review-log replay, predicted retention and workload under fixed ratings; do not use library age or a changed default interval as evidence of learning improvement.

[Google's quota documentation](https://cloud.google.com/vertex-ai/generative-ai/docs/quotas) documents model/service-specific quotas and system limits. Surtitle's former unconditional 10-second minimum was an application policy, not a documented universal requirement. The six-request comparison below found about eight seconds of avoidable inter-request waiting with no observed rate-limit benefit. The adopted policy starts the next approved request when the single native dispatch lane is available, and adds pacing after an actual HTTP 429. The existing positive initial 20-second cooldown, doubling up to 60 seconds, jitter, uncapped longer Retry-After floors and separately approved retry counts remain intact. Three successes reduce the observed interval by five seconds, eventually to zero. Waiting releases the lane so interactive work can proceed. This does not claim unlimited provider capacity: explicit server backoff, frozen scope, budgets, one in-flight owner and unknown-outcome holds remain authoritative.

## Validation and remaining evidence

- Offline native worker test sends a bulk request, approves another job while it is active, verifies no second concurrent send, then verifies the interactive job gets the next turn before the next bulk chunk. Both settle exactly once.
- Queue tests verify cancellation removes waiters, duplicate workers cannot own one approval, and sustained interactive arrivals do not starve a queued bulk job.
- Existing native tests cover pause/cancel during a send, source changes before/after send, unknown charge holds, partial output, restart, superseded workers and local application recovery. The scheduler keeps those boundaries.
- UI tests verify one explicit Start for each purpose, visible scope/cost, unknown-cost disclosure, expired quote blocking, scope invalidation, no implicit approval and failed-start retention.
- The initial regression suite is offline. The authorized two-request synthetic comparison and subsequent six-request natural-speech comparison use isolated validation ledgers and encrypted credential copies; the installed profile is never modified. Unknown billing outcomes are never retried.


## Reproducible local comparison

`e2e/evaluation/ai-preprocessing.ps1` generates a six-minute Windows speech-synthesis loop and runs the actual FFmpeg/Silero preparation and FSRS replay examples. Its outputs stay under a new `work/ai-evaluation/run-*` directory. Supply explicit FFmpeg, pinned Silero model and ONNX runtime paths. It performs no cloud request and does not change application data.

The preparation example compares the retained serial implementation (`prepare_audio_serial`, available only with `development-validation`) with the production `prepare_audio` pipeline in alternating order. Both execute the same tool verification before every child, bounded child watchdogs, source hashes before and after, exact PCM copying, FLAC attachment validation, VAD evidence, settings binding and final durable receipt. The production cap is two encoders plus one decoder. Early FLAC availability is **not** approval or first useful subtitle availability: a quote still needs the full immutable request plan.

The fixture produces three requests and 5,952,000 sent samples (372 seconds including overlap) from 360 seconds of source. Every run checks identical boundaries, FLAC hashes, VAD evidence and preparation binding. The example also cancels during active staged preparation and mutates a separate source copy after extraction; both must return an error and leave no receipt or temporary preparation directory. Unit cases cover strong/weak/no pauses, growing silence, source offsets, selection past EOF and worker cleanup.

Measured production results are recorded in [preparation evidence](evidence/preparation-2026-10-11.json):

| Alternating round | Serial quote-ready | Staged quote-ready | Serial first FLAC observed | Staged first FLAC observed |
| --- | ---: | ---: | ---: | ---: |
| 0 | 36.17 s | 21.39 s | 17.55 s | 13.78 s |
| 1 | 19.78 s | 18.02 s | 9.05 s | 10.93 s |
| 2 | 21.21 s | 16.77 s | 10.04 s | 10.41 s |

Mean quote-ready time is 25.72 s versus 18.73 s (27% less elapsed time in this run). Host load, debug builds, caching and simultaneous build activity caused substantial variance; these are local acceptance measurements, not a general performance guarantee. First-FLAC observation was slower in two rounds, so adoption is justified by complete preparation time and preserved invariants, not a claim of uniformly earlier first output. Actual cancellation and source-change cleanup both passed. [FSRS replay evidence](evidence/fsrs-2026-10-11.json) preserves every transition and comparison result.

FSRS comparison: [latest stable is 6.6.2](https://docs.rs/fsrs/latest/fsrs/), identical to `Cargo.lock` as checked on 2026-10-11. A read-only count found no existing user review rows, so `crates/core/examples/redesign_fsrs_replay.rs` uses explicitly synthetic steady, lapse and overdue histories at three retention settings. All 63 transitions across nine cards match the latest stable API's memory and due dates, and SQLite reopen preserves review history and attached audio. This establishes compatibility and preservation; it does not establish improved retention or justify switching an already-current engine.

## Matched recognition prototype (local and live provider)

[e2e/evaluation/recognition.ps1](../../e2e/evaluation/recognition.ps1) generates fixed English and Japanese clips with Microsoft Zira Desktop and Haruka Desktop, then runs the same PCM through `whisper.cpp` and, only with `-ExecuteProvider`, the existing native validation CLI. Native OAuth and model discovery succeeded; absence of a saved model preference did not prevent evaluation. The copied encrypted credential was removed after recording the report. No installed settings, budgets or data were changed.

[whisper.cpp stable 1.9.5](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.5) links the official b5454 Windows artifacts. The reported binary identifies itself as 1.9.5. Both the release artifact SHA256 and the upstream multilingual base model SHA256 were verified; the model adds 147,951,465 bytes and runs on CPU with four threads. The provider is the discovered GA [Gemini 3.1 Flash-Lite](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/gemini/3-1-flash-lite), global, streamed JSON subtitle output, default thinking, maximum 2048 output tokens, maximum 15 seconds per immutable request.

[Recognition evidence](evidence/recognition-2026-10-11.json) contains reference text, output text, source hashes, cues, measured durations and calculation rules. ## Natural speech and bounded pacing comparison

`e2e/evaluation/natural-pacing.py` reuses both checksum-verified LibriSpeech recordings, preserving the PCM and inserting exactly 0.5 seconds of digital silence between them. The combined input is 6.455 seconds and 15 reference words. The same whisper.cpp 1.9.5/base/CPU4 setup and the same GA Gemini 3.1 Flash-Lite/global/streamed JSON settings receive identical audio. The first provider result is reused for recognition comparison; only six paid dispatches occur in this follow-up.

Local recognition took 1.222 seconds; the first provider run took 1.974 seconds including process/auth/network overhead. Both have one strict normalized word edit out of 15: the reference spells `counselled`, while both outputs use `counseled`. This is a spelling variant, not evidence of a different heard word. One later provider response reproduces the reference spelling. All cue ranges remain inside the audio, but boundaries vary substantially: the provider's first cue ends between 2.34 and 3.54 seconds across repetitions, compared with the automatic MFA reference envelope ending at 2.80 seconds. The local cue ends at 3.68 seconds. Automatic alignment is not human timing ground truth; this trial does not establish accurate word timing or a broadly superior recognizer.

The native validation scope already omits the desktop client pacing policy while preserving exact single-request approvals, immutable manifests, source checks and durable accounting. The harness alternates no artificial floor and a 10-second floor, three requests per condition, waiting from the preceding **actual ledger dispatch timestamp**. It never overlaps sends, edits the clock, bypasses approval, or retries a rejected/unknown request.

| Condition | Actual successive start intervals | Mean dispatch to settlement | Observed 429 / unknown outcomes |
| --- | --- | ---: | --- |
| No artificial floor | 1.854 s, 2.317 s | 1.647 s | 0 / 0 |
| 10-second floor | 10.195 s, 10.195 s, 10.202 s | 1.879 s | 0 / 0 |

The initial no-floor request has no preceding interval. All six requests settled once with known token usage and STOP, and share an identical request-body hash. The 10-second gate added 24.824 seconds of artificial waiting overall. Raw Retry-After headers are not exposed by the existing validation report; no 429 occurred, so their absence is not asserted. Three requests per condition on one account/model and a short repeated clip do not establish sustained throughput, other-model quotas or server load tolerance. Repeated input, caching and changing load may affect latency. These limits do not justify retaining a universal delay when serial dispatch and actual-server backoff are already enforced.

[The natural-speech/pacing evidence](evidence/natural-pacing-2026-10-11.json) records all frozen digests, request identities, exact starts, settlements, outputs, usage and source provenance. Price discovery again returned 403; all charges remain null/unpriced. The total [published-rate](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing) estimate for the six requests is $0.001233–$0.001809, not an invoice. The copied encrypted credential was removed, and its original bytes were unchanged.

The SQLite migration executes in one immediate transaction. Only legacy interval=10,000 with no observed cooldown is reset to zero. Actual observed intervals, server cooldowns, retry floors, approvals and unknown charge holds survive migration and repeated reopening. Native tests cover immediate next-chunk dispatch, continued exclusivity while a request is in flight, migration with a future Retry-After, source/budget rechecks during cooldown, cancellation and gradual recovery to zero.

After adoption, the AI library suite passed 246 tests (five harness entries are ignored in the ordinary run: three separately executed integrations and two subprocess helpers exercised by their parent tests), native AI jobs passed 35 tests, and the inline approval UI passed 12 tests. Strict Clippy passed for `surtitle-ai` and `surtitle` across all targets/features. The required spoken/native/six-hour executions are recorded separately below; no additional paid request was used to validate this policy change.

## Required native and six-hour acceptance

Final queue review reproduced a source-binding gap: an audio worker could verify its original file, wait behind another request, and then send after that file had been replaced in place. A worker that waited now hashes the original media again after acquiring its dispatch turn, on a blocking worker, and rechecks cancellation/current approval before reserving any request. The deterministic regression replaces bytes at the same path and length while holding the lane. It verifies zero provider sends, zero attempts, unchanged subtitles, a source-review state, and released worker/lane ownership. All 34 application AI job tests passed on Rust 1.99 after this correction; normal queue waiting still does not require another approval.

The required runner verified eight exact integration tests with zero skips on 2026-10-11: all six `windows-native` tests, the `windows-six-hour` test and the `windows-spoken` test. These use actual FFmpeg, the packaged MPV/ONNX runtimes and the pinned Silero model, with no cloud request or installed-profile mutation. [Native acceptance evidence](evidence/native-acceptance-2026-10-11.json) records each named test and duration.

The six-hour input is the existing six-minute synthetic English speech loop repeated sixty times. Production staged preparation completed in 112.79 seconds, preserving all 345,600,000 core samples in 180 contiguous chunks. Context raises sent samples to 362,784,000; every request stayed within 186 seconds. The receipt retained 331,616,017 bytes and removed its temporary decoded PCM. Peak Rust-process working set was 49,152,000 bytes; external FFmpeg memory is excluded. This validates long-duration continuity, bounded preparation and cleanup, not transcription quality on six hours of natural speech.

The real-speech test passed on Rust 1.99 in 14.39 seconds using two short [LibriSpeech test-clean recordings](https://www.openslr.org/12) and the exact pinned [MontrealCorpusTools alignment commit](https://github.com/MontrealCorpusTools/aligned-librispeech/tree/5143690d1a6ebcd37b7f4d1b0f9fa8c83944aba5). `e2e/evaluation/acquire-spoken-fixtures.py` retains original URLs/hashes and checks all six existing fixture hashes. Ordinary FFmpeg PCM16 rewrapping reproduces the expected WAV files while leaving every original PCM sample unchanged; the test constants were not changed. The two utterances contain 52,400 and 42,880 samples, separated by an explicitly constructed four-second digital pause. All 159,280 selected samples survive preparation exactly. The two reference speech cues remain confirmed, and only an authored cue inside the pause receives the local warning; valid speech does not gain another confirmation gate. Stale warning acknowledgment is rejected, and current acknowledgment preserves the original cue content. [Spoken-pause evidence](evidence/spoken-pause-2026-10-11.json) records these results. This validates local warning behavior, not recognition accuracy: the cue response is authored, MFA timings are automatic reference anchors, and two clean English utterances do not represent noisy or conversational media.


## Current Silero and ONNX Runtime prototype

The latest [Silero v6.2.3](https://github.com/snakers4/silero-vad/releases/tag/v6.2.3) streaming `silero_vad.onnx` was downloaded from the exact upstream tag. Its SHA256 is identical to the pinned v6.2 artifact (`1a153a22f4509e292a94e67d6f9b85e8deb25b4988682b7e174c65279d8788e3`). The package changes do not require replacing the application's model bytes. The newer separate offline sequence model has a different execution contract; this comparison retains the bounded streaming model.

[ONNX Runtime v1.31.0](https://github.com/microsoft/onnxruntime/releases/tag/v1.31.0) was actually compared with packaged v1.29.0, using the official Windows x64 CPU archive with its published SHA256 verified. The archive, license, third-party notices and source commit are retained in the isolated evaluation directory. `e2e/evaluation/vad-runtime.ps1` runs `crates/ai/examples/redesign_vad.rs` in six isolated processes (three alternating pairs) against identical six-minute PCM through the production Silero wrapper. Separate processes prevent the dynamic loader from reusing the first runtime.

[Runtime evidence](evidence/vad-runtime-2026-10-11.json) records exact hashes and every timing. All pause evidence and all three chunk boundaries were identical. Mean inference was 1,322.92 ms for packaged1.29 and 1,398.21 ms for candidate1.31 (5.69% longer in this trial); initialization is reported separately. The current packaged runtime is retained because the candidate did not demonstrate a material latency or output benefit. This is one synthesized fixture, and source-build versus upstream-prebuilt configuration and shared-host load confound a general version-performance claim. No runtime or model was silently replaced, and no speech-quality superiority is claimed.
