# Rendering evaluation — 2026-10-11

## Decision and acceptance boundary

Implement **native libmpv with a stable video viewport, adjacent study panels, and opaque overlay exclusions** as the first production candidate. Replace the blanket “any modal hides the entire video” policy with explicit surface geometry and input ownership. Use `SetWindowRgn` on the host HWND to subtract only intersecting, opaque popup rectangles. The remaining video continues displaying at its original size. This is a change to the presentation architecture, not unconditional retention of the existing behavior.

The implemented route passed the real WebView2 154.0.4258.62 application test at 1024×700 and 1440×940 with D3D11 WARP explicitly forbidden, then passed in a normal installed production release at 1024×700, 1280×800, 1440×900 and 1440×940. Native-window screenshots show the opaque playback-settings card through the exclusion while uncovered video remains visible. Video dimensions remain unchanged; playback advances while the card is open; checkbox input, Tab containment, Escape dismissal and focus restoration pass. The measured viewport heights were 343, 443, 543 and 583 CSS pixels respectively (devicePixelRatio 1; actual HWND DPI 96). Later physical 125/150/200% and mixed-monitor checks pass geometry and input; the discovered 200% window-fit failure and its verified correction are recorded below. Japanese IME is proven in the adjacent production phrase input and four isolated native candidate dialogs; broader stress remains unmeasured. The focused native proof must not be described as full acceptance of every gate below. Any failed integration gate must be fixed or lead to a composition prototype, not be waived by DOM mocks.

Transparent surfaces, backdrop blur over moving video, soft shadow blending, and arbitrary transform/opacity animations crossing the video are outside the region-exclusion contract. Surface design must use opaque cards and stable geometry. A backdrop covering the whole viewport would erase the benefit and must not be used for routine learning controls.

## Required implementation contract

1. Keep the learning video viewport independent of progress, jobs, notices and auxiliary content. Routine panels occupy reserved adjacent space or an opaque popup with an explicit exclusion; they do not create a new vertical stack above the video.
2. Represent visibility, occlusion geometry and input ownership separately. A modal may block player commands while the uncovered video remains visible. Clip the actual native host, including its mpv descendants; preserve serialized bounds/hide placement and reject stale media/surface revisions.
3. Register opaque popup bounds, including all affected edges, before making the popup interactive. Do not animate opacity/translation across a live native surface. Wait for native placement acknowledgement when required to prevent the first frame from showing the HWND over the control. Closing must retain exclusion until the popup is removed.
4. Convert CSS coordinates to physical pixels consistently; intersect exclusions with the current viewport; clamp invalid/out-of-bounds rectangles. Refresh after resize, scroll, DPI changes and surface movement. Reset regions on disposal, navigation and player replacement. Use Win32's region ownership rules to avoid leaking GDI handles.
5. If a design requires translucent video overlays or the native acceptance gates cannot pass reliably, build the GL/ANGLE + WebView2 composition candidate and run the same gates before choosing the host. Do not silently restore blanket hide behavior.

## Native acceptance gates

- Real GPU, production-equivalent decoding and visible native surface: H.264, MPEG-4 Part 2, HEVC, VP9, representative AV1, multi-audio and subtitle fixtures. Check nonzero video dimensions/frames, audio/video synchronization, exact sentence seeking, repeated loops, playback rates and pause boundaries.
- At 1024×700, 1280×800, 1440×900 and 1440×940, opening activity/translation/vocabulary, progress updates and errors must not reduce the agreed video rectangle or blank uncovered video. Verify native pixels, not only DOM bounding boxes.
- Open, reposition and close two overlapping opaque surfaces; rapid resize; 100/125/150/200% scale; move between monitors; minimize/restore; fullscreen; navigation while a placement request is pending. No stray native rectangle, stale hole, flicker or GDI growth after repetition.
- Popup hit testing, outside click, modal-blocked player clicks, Tab/Shift+Tab/Escape, Japanese IME composition, selection, screen-reader labels and focus restoration must work while playback continues. A hidden/inert panel must not retain keyboard shortcuts.
- If composition is selected, additionally prove no per-frame JS/IPC copies, real hardware adapter identity, frame lifetime/fences, renderer restart and GPU-device loss recovery; measure startup, CPU/GPU, memory, frame drops, 1080p/4K and resize latency against the HWND baseline.

- [Electron sharedTexture](https://www.electronjs.org/docs/latest/api/shared-texture): external GPU texture import and explicit experimental status.
- [Electrobun WebGPU](https://framework.blackboard.sh/electrobun/apis/webgpu/): native GPU surfaces and native SDK route.
