# Surtitle architecture

Surtitle is a Windows 11 x64 desktop application built with Tauri, React, TypeScript, Rust and SQLite.

The React renderer calls generated, typed IPC commands and listens to player and resource-change events. It cannot execute shell commands, read service-account keys, run SQL, or send Vertex requests. The local Tauri window is the only IPC client. Remote documents are never loaded into the application WebView.

| Component | Responsibility |
| --- | --- |
| `surtitle-core` | Learning data, subtitle parsing, FSRS scheduling and portable archives |
| `surtitle-tools` | Tool discovery, executable selection, receipts, bounded processes and managed updates |
| `surtitle-ai` | Request preparation, Vertex adapters, encrypted credentials and the durable charge ledger |
| Tauri application | Service composition, IPC commands and the native child video window |

## Code organization

The renderer separates application composition (`src/app`), learning features (`src/features`) and shared transport/contracts/UI (`src/shared`). Library, study, cards/review, AI approval, settings/tools and transfer each own their commands and presentation. Playback, transcript review and draft study remain within the study feature. Cross-feature dialogs are composed by their parent; AI job actions report a transcript-review intent instead of importing the study dialog. IPC data contracts are shared, while business logic stays with its feature.

Appearance, notifications, native-surface geometry and application data have separate providers. Native `data-changed` events identify the resource, entity, process epoch and revision. Shared subscriptions coalesce notifications and invalidate affected queries; snapshot domains use `get_snapshot_patch` rather than rereading all data. Playback ticks update the player independently. Registration, focus/network/visibility recovery and one visible-window 60-second checkpoint recover missed changes; unchanged checkpoints fetch no data. Revision gaps trigger recovery, while epoch changes and restore invalidate persisted-data queries. Older in-flight reads cannot overwrite newer revisions or cross a restore boundary. Some explicit mutation flows still request a full snapshot.

The generated command map binds command names to native argument/result types. Runtime validators and shared Rust/TypeScript fixtures check event/checkpoint envelopes and command-result primitive/container shapes. Nested legacy DTO validation is not fully generated; Rust serde and native use cases still enforce semantic constraints. Generate it with `pnpm generate:ipc` after command changes and verify it with `pnpm check:ipc`.

Settings and existing-card text edits use durable sessions with automatic saves after 500 ms idle or blur. Raw incomplete fields survive navigation; acknowledged drafts survive restart. Saves are serialized, preserve newer local input and reject stale revisions. Conflicting input stays available for explicit recovery. Ordinary navigation does not ask for an unsaved-changes confirmation. Window closing waits for registered saves, detached editors and later input; a persistence failure keeps the window and inputs available for retry.

Phrase and subtitle editors save drafts durably, separate from the committed card or subtitle. Drafts survive navigation and restart, and can be kept with **Continue later** or explicitly discarded. Their source bindings are checked before saving learning content. A changed source or restored archive requires explicit reconnection to current subtitles while preserving the draft text.

Tauri command adapters live under `src-tauri/src/commands`; application use cases and runtime ownership live under `src-tauri/src/application`. Dependencies flow from commands to application to the core/tools/AI crates and native player. Application code never calls IPC commands.

The playback coordinator owns the synchronization boundary around native operations, database reconciliation and poll-and-save. Durable data has separate authorities:

| Store | Ownership |
| --- | --- |
| `learning.sqlite` | Cards, subtitles, review history and portable phrase/subtitle drafts; a learning generation rejects writers from before a restore |
| `workspace.sqlite` | Device-local, revisioned raw input for settings, existing-card edits and import; never AI approvals or credentials |
| `preferences.json` | Committed non-budget preferences and the credential identifier |
| `charges.sqlite` | Budget limits, reservations and usage; old JSON budget copies are ignored |

Current settings patches update either non-budget preferences or the complete budget group under revision checks. Budget patches write only the ledger. Preferences save atomically before their in-memory value changes; a later native reconfiguration failure requires readback and explicit feedback. The legacy full-settings command remains compatible but spans two durable stores and is not atomic. Existing-card saves update only editable content, preserving current audio, source snapshots, schedules and review records. Restoring learning data advances its generation atomically; old existing-card workspace drafts remain readable as stale input and cannot overwrite restored content.

Core storage methods are grouped by learning responsibility, with one source-cue selection validator shared by replay and card creation. Both confirmed and applied AI-generated subtitles are usable; generated status and review markers remain visible. AI modules separate request construction, output parsing, chunk planning, transcript reconciliation and ledger operations. The development validation CLI rejects invalid arguments before opening its data root or recovering the ledger. See [AI behavior](ai.md) for approval, dispatch and settlement rules.

Transcribe text and word timing are validated separately. `SubtitleSegment.timingPrecision` is `cue` for usable timings (the legacy default) or `source_block` for original text with only its submitted-audio bounds. Source blocks participate in ordinary study and preserve exact source context, but never arm synchronized captions, caption-group stops or SRT/VTT. Word-anchor reconciliation chooses one result inside shared submission intervals and keeps original alternatives.

Build and packaging helpers are documented in the [script reference](../scripts/README.md) and [native runtime guide](native-runtime.md).

## Study surface and native rendering

Video and the current subtitle are the primary study surface. User actions open one companion panel at a time; progress never opens a panel or changes video bounds. React Aria owns modal portals, focus containment/restoration, dismissal and IME-aware Escape. Native video uses a stable child HWND with opaque popup shapes, including uniform rounded corners, excluded through `SetWindowRgn`, preserving uncovered playback. This contract requires opaque surfaces and stable geometry; transparent effects and arbitrary transforms across the video are unsupported. Failed placement can temporarily hide the surface for recovery. Companion reveal and player resizing share one width transition; the companion is clipped against confirmed and in-flight native bounds until those pixels are clear. Opening focus waits for endpoint placement acknowledgement. Video ancestors never transform. Outgoing tab views are retained inert, while review exits contain presentation only. Reduced motion also disables animated reveals and smooth transcript following.

The HWND approach preserves the supported libmpv codec path. Browser video trials lost pictures for supported files, while the GPU composition prototype needed decoder copying and further production integration. Those alternatives are not shipping providers. The [historical evidence index](redesign/acceptance.md) retains the bounded comparisons.

Window fitting derives normal bounds and minimums from the monitor work area, current DPI and measured visible frame. It keeps a 1280×720 logical client minimum when it fits and caps dimensions on smaller work areas. The initial size is 1600×900; Appearance offers 1280×720, 1600×900 and 1920×1080 presets as immediate device-local actions. Valid saved placement takes precedence over the initial size. Windows drags magnetically align the visible frame within 12 logical pixels of work-area edges without resizing. Setup fits the hidden window before showing it; coalesced move/resize/scale/focus events update constraints without changing system DPI. System window states stay with Windows unless a preset explicitly restores normal display. Compact-height layout keeps primary controls reachable.

Phrase lists above 40 results and long subtitle lists use TanStack Virtual. Dynamic row measurements and retained focused/editor rows preserve wrapping and keyboard continuity. Filtering and initial snapshot construction still scale with the dataset; virtualization is not database pagination.

## Behavioral boundaries

The learning database is separate from operational settings, credentials, charge reservations and prepared jobs. Restoring learning data validates the archive, creates a SQLite backup, then replaces learning records in a transaction. The playback coordinator holds native commands and poll-and-save ticks throughout replacement and player reconciliation. If the current item survives and its file exists, it reopens paused at the restored position with the restored audio choice, subtitles and sentence endpoints. Removed or missing items leave the player stopped and detached. Once replacement commits, later cleanup or player failures return warnings about a completed restore; they do not claim rollback or invite a second replacement. The restore event still invalidates old editor sessions. CSV/TSV exports escape spreadsheet formulas; ZIP import rejects traversal, symlinks, duplicate entries and unexpected files. See [export and restore](data-transfer.md) for formats, size limits and audio retention.

Playback resumes only after the native player confirms that the requested file has loaded. Positions emitted during loading cannot replace the stored resume point. An audio choice is stored as the absolute FFmpeg stream index; mpv track IDs are mapped through `ff-index` rather than treated as interchangeable IDs. Transcription receipts and saved cards retain the selected audio index. Basic playback uses mpv metadata without requiring FFmpeg installation.

Optional sentence pauses are enforced in the native player. The common core groups consecutive precise source cues using terminal punctuation, two-second gaps, and the final subtitle, excluding source-block rows. Common abbreviations continue into the next cue; overlapping cues remain together. These are cue-aligned heuristics, not inferred word times: several sentences inside one cue share its recorded end. Resume and free seeking select the next later endpoint, subtitle changes replace the endpoints, and explicit source-range playback or looping takes priority. The setting starts disabled. Vocabulary candidates can replay their complete adjacent source-cue range through a command that derives the times from the current database.

The Study page's right-edge **Transcript** tab opens and closes its subtitle panel. **Add or switch subtitles** in the subtitle list groups embedded text extraction, transcription entry, file import and **Saved subtitles**. Transcription opens the Study page's shared workspace and begins local audio preparation. One Start action approves the scope and quote, including the price-unknown disclosure when applicable. New whole-recording, range and re-transcription jobs publish each received part into the normal list, with quality review optional. Older saved jobs require an explicit local application. Importing a file or extracting an embedded text stream saves the previous edition without an extra replacement checkbox and verifies the extraction source. Previous editions can be restored. Playback captions remain separate: **Playback settings** is available directly in the player, with **Use these captions for study** opening the source dialog for that stream. Image subtitle extraction is unsupported.

Publication sessions in the learning database capture the initial edition, expected full rows, generated-row ownership, received coverage and protected edit ranges. Activation after execution approval claims the requested interval from older running jobs. Each projection and its record commit atomically; unreceived old cues remain whole, local edits are protected and completion does not replace all rows again. Subtitle changes do not invalidate the frozen audio request. Restore/import detaches publication, and learning backup restoration clears operational authority without altering the separate charge ledger.

Cards may cite one usable subtitle or an ordered, adjacent set of confirmed or applied AI-generated subtitles. The database validates IDs, media ownership and adjacency and derives their audio range. A single source-block cue permits an explicit bounded `sourceRange`; the chosen card audio still has a 180-second maximum. Each card stores immutable `sourceCues`, including original text, translation, full source bounds and timing precision, separately from its chosen card range and extracted clip context. Editing card text changes neither these snapshots nor audio, scheduling or review history. Removing a library item preserves original files and saved cards; deleting a card removes its review records. Unreferenced audio clips are not automatically deleted.

FSRS remains the scheduling engine, preserving existing memory state and review history. The review page tracks completed schedule revisions rather than permanently excluding a card ID. An Again rating can return at its newly stored due time while the page stays open, with the answer concealed. A stale snapshot cannot immediately offer the already-rated schedule again. The next due time schedules a local wake-up; ordinary review never sends an AI request.

URL imports are background jobs with explicit cancellation and retry. Direct media URLs stream without CLI tools; completed public YouTube videos use independently selected yt-dlp, Deno and FFmpeg. The app limits concurrent downloads to two, caps stored data at 100 GiB per job, and preserves a 256 MiB free-space reserve. A partial download stays in an app-owned staging directory and is removed on failure, cancellation or startup recovery. Interrupted jobs never restart automatically. Completion emits a library refresh event. Reported stored bytes include intermediate merge files and are not a bandwidth or ETA measurement.

Bundled mpv uses its own metadata and codecs for basic playback. FFmpeg is unnecessary until extraction, conversion, or merging. mpv is loaded from an absolute bundled DLL path with restricted dependency search; its config, scripts and URL hooks are disabled. Windows always uses real libmpv. The deterministic Linux adapter is compiled only with `e2e-test`, cannot substitute for the Windows native test, and is not a supported Linux product.

External executable discovery and managed updates belong to `surtitle-tools`; see [tool management](tools.md) for selection, process lifetime and update rules. Development checks and their coverage are described in the [test guide](testing.md).
